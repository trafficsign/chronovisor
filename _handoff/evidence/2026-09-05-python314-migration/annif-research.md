# Annif の Python 3.14 移植調査

2026-09-05。検証は隔離環境で実施し、本番の Annif・モデル・設定は変更していない。

Annif 1.4.1 は、依存メタデータの3行を修正すると通常版 CPython 3.14.7 で動作する。Python、NumPy、SciPy の制約を更新し、Annif の実装ソースと fastText binding は維持した。[候補パッチ](annif-python314.patch)を保存した。

| 環境 | Annif | NumPy | SciPy | scikit-learn | fasttext-numpy2 |
|---|---|---|---|---|---|
| 3.13.12・現行条件 | 1.4.1 | 2.2.6 | 1.15.3 | 1.7.2 | 0.10.4 |
| 3.14.7・移植候補 | 1.4.1 | 2.3.5 | 1.16.3 | 1.7.2 | 0.10.4 |

固定合成データ16文書・4分類では、TF-IDF と fastText の学習・推論、3.13の成果物を3.14で再学習せず読み込む処理が成功した。4問×2方式の候補・順位・CLI出力スコアが一致した。ただし、この小規模データの fastText はスコアが一様に近く、分類品質の確認としては不十分だった。[生の結果](annif-port.json)

そのため、同じ設定で512文書・4分類の追加確認を実施した。3.13で学習した fastText は4問すべて正解し、首位スコアは0.9620 / 0.9401 / 0.9433 / 0.9271。この学習済みバイナリを3.14環境へコピーすると、再学習なしで4問すべての候補・順位・CLI出力スコアが一致した。モデルファイルの SHA-256 も変更前後で一致する。[追加検証](annif-fasttext-quality512.json)

Annifから乱数seedを固定できず、学習は両環境とも8スレッドで行った。確認できたのは固定合成データでの動作と既存成果物の再利用であり、実UDCデータ全体の品質・長時間学習・メモリ消費を保証する結果ではない。起動時間は同時に全体pytestと常駐サービスが動いていた条件の参考値で、Python単独の性能差とは断定していない。

公式の Annif 1.4.1 / 1.4.2 はまだ Python <3.14 を要求する。[公開メタデータ](https://pypi.org/pypi/annif/1.4.1/json)、[公式の3.14対応Issue #931](https://github.com/NatLibFi/Annif/issues/931)。そのままの配布物ではSciPy 1.15.3のcp314 wheelも使えず、現在のホストではソースビルドが失敗する。

移植の技術的実現性は確認できた。本番へ切り替えるには、独自版の再現可能な配布・保守、実データでの品質・性能検証が必要である。今回の追加調査では本番移行を実施せず、Chronovisor の Annif 起動設定は3.13のまま保持した。oMLX アプリ内蔵の Python 3.11 も変更していない。
