目的

  • 下の完成画像を単なる参考ではなく、Chronovisor Dashboard の 展開中 Processing Lanes + Decision Trace 親子領域に対する視覚正本・受入基準にする。
  • Processing Lanes の active stage から、Execution Plan、Context、実際の Reasoning、Primary、Challenger、必要時の Tie-break、Artifact、Decision / Hold までを一本の読み取れるハーネスとして live 表示する。
  • 見た目だけを似せず、既存の実測 event replay、safe quorum、context admission、model activity と一致する状態だけを発光させる。

完了の意味: 固定 fixture で「ぱっと見が完成画像とほぼ同一」、live では表示経路が実行証跡と一致し、GitHub-backed runtime の SHA・health・指定 viewport の DOM 実測まで合格していること。

視覚正本

  • 正本に固定するもの: 濃紺の航空管制盤風背景、二つの細い外枠、monospace の情報密度、細い角丸ハーネス、紫・橙・緑・赤の restrained glow、ノード間余白、上段から下段へ流れ込む連続性。
  • fixture で変えるもの: workflow、active stage、elapsed、job id、required / selected / effective context、actual think、active lane、repair attempt、quorum result、event count。
  • 画像の HIGH や 112K を hardcode しない。実際の選択が medium なら MEDIUM、役別 context が異なるなら各 role binding の実値を光らせる。

やってはいけないこと（必須）

  • 画像を背景に貼り、その上へ不可視の操作要素を重ねて「再現」としない。
  • 汎用 DAG auto-router、任意 graph DSL、幅ごとの別 SVG、1実装しかない抽象層、新しい data API を作らない。
  • 内部ハーネスを毎 frame 自動配線しない。固定 path を state class で更新し、動的に再計算するのは選択中 Processing stage から Trace 入口への一本だけにする。
  • 既存の /api/activity-stream、poll fallback、/api/local-consensus、observed-event replay を置き換えたり、存在しない synthetic progress を生成したりしない。
  • 未検証の model に high を送らない。能力・入力・capacity が不明なら現行互換の medium に戻す。
  • Artifact / Decision → Hold を通常の no-safe-quorum 経路として描かない。quorum failure は Artifact 前から Hold、Artifact 後は seal failure だけ。
  • local の古い checkout、未追跡の .env、_handoff/2026-06-11_0042_recall-redesign.md、logs/、他タスクの実験を変更・stage・commit しない。
  • push の明示許可前に push / runtime restart しない。許可後は push 前の restart も禁止する。

  • Processing Lanes を親とし、active Local Decision の Trace を直下へ展開する。現在ページ下部にある単独 Decision Trace を重複表示しない。
  • idle / 完了時は既存の意味要約へ折り畳めるが、参照画像との主比較は展開 fixture で行う。
  • Primary / Challenger / Tie-break の内部 path、Repair loop、Agree、Artifact、Decision、Hold は固定座標。state は pending / active / done / skipped / error class と実ラベルで表す。
  • Artifact と Decision は各1個。Pair 合意と Tie-break 合意は同じ Artifact に合流し、Single-model bypass も同じ Artifact へ入る。

Adaptive reasoning と役別 context の真実性

  • UI phase の前に、既存の共有境界 structured_think_mode を最小の純粋 selector として拡張する。task / lane / role、required / effective context、検証済み model capability 以外の推測値は使わない。
  • 通常は medium、simple / bounded repair は評価合格時だけ low、Tie-break / high-impact は品質・JSON-valid率・latency・headroom・model capability の全 gate 合格時だけ high 候補とする。未知値は medium。
  • policy version / hash、selected think、selection reason、required / selected / role-effective context を audit へ残す。Dashboard は既存 lanes[] へ最小投影し、別 endpoint を作らない。
  • shadow / paired replay と限定 canary を通るまで production で low / high を選ばない。表示は transport に渡した実値だけを使う。

実行手順

  1. Phase 0 — 最新 GitHub 正本と保護範囲を固定。 git fetch origin 後の exact origin/main から clean branch / worktree を作り、Dashboard / decision / tests の現責務を再監査する。dirty checkout の未追跡資産は一切移動しない。基準 SHA と対象ファイルを実行ログへ記録する。
  2. Phase 1 — Reference contract を test asset 化。 この Plan の PNG と SHA / 寸法を照合し、A–H の固定 JSON fixture を既存 test 配置規約に置く。dynamic text を固定し、比較する親子 panel group の capture bounds を定義する。
  3. Phase 2 — Adaptive reasoning を証拠付きで導入。 既存 model-eval / adoption evidence から role ごとの supported reasoning level を確定し、共有 selector、medium fallback、policy hash、audit reason を実装する。unit / transport / fail-closed test と shadow paired replay を通し、production 選択は canary gate まで閉じる。
  4. Phase 3 — 実効 plan 値を既存 payload へ最小投影。 active marker / session / decision audit の既存値から lanes[].context_tokens と actual think を組み立てる。redaction と過去 record 互換を守り、不明値は捏造せず — とする。
  5. Phase 4 — Processing / Trace を親子化。 Processing Lanes の既存 HTML・SSE・poll を維持し、active Local Decision の直下へ Trace mount を移す。旧 standalone Trace は削除し、ARIA live summary と折畳み keyboard 操作を保持する。
  6. Phase 5 — 固定 SVG harness を実装。 正本座標から内部 node / path を一度だけ定義し、Artifact / Decision 各1個、repair loop、pair / tie合流、Hold topology を固定する。generic routing code は作らない。
  7. Phase 6 — 既存 observed replay を SVG state へ接続。 renderer の event queue / reduced-motion / no-synthetic-progress 契約を残し、既存要素を再生成せず class・text・必要な data-* を更新する。ResizeObserver は上段から入口への1 path の d だけを更新する。
  8. Phase 7 — 正本 style と accessibility を仕上げ。 背景、枠、monospace、1–1.5px rounded harness、glow、focus、色以外の state signifier、screen-reader summary を実装する。狭幅は単一 SVG を処理領域内で横スクロールし、ページ全体 overflow と別 SVG を作らない。
  9. Phase 8 — A–H と geometry を自動検証。 Python payload tests、Node VM replay、DOM/SVG の個数・座標・交差・ellipsis、keyboard / reduced-motion を最小の既存 test harness へ追加する。pixel diff だけに依存しない。
  10. Phase 9 — 1586×992 visual calibration。 Chromium、DPR 1、zoom 100%、font ready、motion off で親子領域を撮影し、reference overlay / diff と DOM 実測を同時に残す。A–H 全状態と狭幅 980×1000、680×1200、375×900 を確認する。
  11. Phase 10 — 変更範囲を検証・commit。 targeted tests、git diff --check、本番 lock から隔離した全体 test を通す。policy / payload / UI の意味ある単位ごとに意図した file だけ commit し、他者変更を含めない。
  12. Phase 11 — 明示許可後に GitHub-backed runtime へ反映。 push 許可がなければここを blocker にして止める。許可後は push → Dashboard（必要な場合だけ関連 decision service）restart → runtime archive direct_url.json SHA → health の順を守る。
  13. Phase 12 — live acceptance と Plan close。 live API / event audit / actual Ollama request と発光経路を照合し、指定 viewport の screenshot・DOM geometry・console・overflow を確認する。archive SHA が pushed SHA、health が drift=false の時だけ Plan を done にする。

Rollback / release guard

  • Adaptive policy は既存 medium 固定へ即時戻せる独立 commit / flagless code path とし、invalid plan / missing capability は自動で medium。
  • Dashboard は既存 API 契約を保つため、UI commit の revert だけで旧 HTML Trace へ戻せる単位にする。
  • canary で JSON-valid率、safe resolution、latency、context ceiling、memory admission のいずれかが frozen baseline を下回れば low / high promotion を止める。
  • restart は影響サービスだけ。UI-only 最終差分なら Dashboard のみ、policy runtime が変わる場合だけ実行経路を所有する必要最小サービスを追加する。
