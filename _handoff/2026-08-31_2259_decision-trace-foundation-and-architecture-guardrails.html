Plan: Chronovisor Decision Trace 投影基盤の置換と増築防止

ready plan_d505a7bd888242138dcf9527f8f22ef7 2026-08-31T22:59:27+09:00 baseline ca7b093

目的

結論: Dashboard全体や実行ロジックをゼロから作り直さない。一方で、Decision Traceの 「実行事実 → 表示状態 → グラフ → SVG描画」の境界は、既存コードへの追加工事ではなく一つの経路へ置換する。
  • 実処理の状態と、Decision Trace / Processing Lanes の表示を一対一で追跡できるようにする。
  • 線・ノード・分岐の構造を実行途中で変えず、固定されたレール上で状態だけが前進する表示にする。
  • Ingestだけの特例を廃止し、Ingest / Recall / Audit / Improve / Repair / Typed Graph の全レーンを同じ投影契約で表示する。
  • 今後の修正が再び「増築」にならないよう、禁止事項を自動検査するアーキテクチャテストとDashboardチェックSkillを残す。
  • 本番反映前にローカルpreviewで全状態をスクリーンショット・DOM・SVG実測し、ユーザーが結果を確認できる状態にする。

設計判断

判断採用理由
Dashboard全面再構築しない正常なAPI、実行ロジック、イベント、監査ログ、外観まで捨てる必要はない。
Decision Trace投影境界置換する現在はbackend projectionの後でfrontendが再推論し、複数の表示経路が同じ画面を上書きしている。
描画技術既存SVG/CSSを再利用新しいgraph libraryやframeworkは不要。固定座標とclass切替だけで要件を満たせる。
移行方法replace, then delete新旧経路を恒久併存させない。切替と同じ作業単位で旧推論・旧geometry mutationを削除する。
ロールバックGit revertfeature flagを増やさず、完全に整合した旧版へ戻す方が単純で安全。

最小データ契約

  • execution_id: 新しい実行だけが表示状態を初期化できる。
  • graph_id: flow topologyを特定する。同じ実行中は不変。
  • revision: 単調増加。古いpoll結果は破棄する。
  • nodes / edges: ID、label、state、接続関係。rendererが業務状態を推測する材料は渡さない。
  • selected_branch: 分岐結果はproducer/reducerが明示する。rendererが点線や色から逆算しない。

新しい抽象framework、factory、plugin、外部dependencyは作らない。既存の project_decision_trace() を唯一の境界として深くし、並列endpointは増やさない。

壊してはいけない不変条件

  1. 単一正本: Decision Trace / Processing Lanes のrendererは TraceView 以外のraw status、global lanes、task_role を読まない。
  2. 固定レール: 同じ execution_id + graph_id の全frameでpath d、node座標、transform、viewBoxが一致する。
  3. 単調前進: completeになったnode/edgeは、同じexecution内でpendingへ戻らない。古いpoll responseは表示を巻き戻さない。
  4. 枝の意味: diamondは二つ以上のlabel付き出口がある場合だけ使用する。分岐のない処理は通常nodeにする。
  5. 接続完全性: 全edgeの始点・終点が存在し、切断・孤立・同一出口から無関係な入口への接続がない。
  6. 状態の一意表示: 進行済みedgeは一本の実線として見え、同じ位置に点線が残らない。未進行edgeだけが点線になる。
  7. 全レーン同契約: Ingest / Recall / Audit / Improve / Repair / Typed Graph に専用rendererや隠れstate machineを作らない。
  8. animation非干渉: 500msの表示queueは到着済みstateを順に見せるだけで、state reductionやSVG topologyを変更しない。

やってはいけないこと（必須）

  • 症状ごとの座標補正、特定preview/stateだけのCSS例外、Ingest専用分岐を追加しない。
  • 新しい経路を追加したまま旧経路を残さない。移行完了条件に旧コード削除を含める。
  • renderer内で setAttribute("d", ...)、setAttribute("transform", ...)、viewBox/heightの状態依存変更をしない。
  • 描画側でruntime status文字列を解析し、branch、lane、完了位置を決めない。
  • 実体イベントを確認せず、見た目だけを根拠にdiamondやbranchを作らない。
  • 新しいUI framework / graph library / state libraryを追加しない。
  • preview検証とユーザー確認より前にpush・本番再起動しない。
  • 無関係なdirty filesを編集・stage・commitしない。

実行手順

  1. Phase 0 — baseline固定: HEAD/origin/runtime SHA、dirty worktree、preview/prod process、現行testsを記録する。A–Fの既存state matrixと全レーンの基準スクリーンショット・DOM/SVG snapshotを保存する。
  2. Phase 1 — 実イベント契約: producer → API → project_decision_trace() の全状態遷移を列挙し、各node/edge/branchを根拠イベントへ対応付ける。根拠のないdiamond/edgeをこの段階で削除対象にする。実イベント表が完成するまでUI実装へ進まない。
  3. Phase 2 — red architecture tests: 固定geometry、revision単調性、no-regression、edge endpoint、branch topology、全6レーンcoverage、renderer raw-source禁止を失敗するtestとして先に追加する。
  4. Phase 3 — projection置換: project_decision_trace() から最小 TraceView を返すpure reductionへ統一する。新endpointや並列adapterは作らず、既存consumerを一つずつこの出力へ切り替える。
  5. Phase 4 — fixed renderer: Decision Traceを固定SVG topology + state class/textだけのrendererへ置換する。logical edgeごとに安定IDを持たせ、mount後にgeometryを変更しない。
  6. Phase 5 — Processing Lanes統一: Ingest / Recall / Audit / Improve / Repair / Typed Graphを同じ TraceView から描画し、各レーンの末端整列・接続・clippingを検証する。
  7. Phase 6 — 旧経路削除: processingLaneForTrace() の再推論、ingestJobTraceState() の第二state machine、updateDecisionSvgHarness() のgeometry mutation、重複mega-SVG modeと対応する古いtestを削除する。削除が終わるまで移行完了にしない。
  8. Phase 7 — presentation queue: 同時到着した複数stateを約500ms間隔で順に表示する小さなqueueを追加する。新execution/revisionでcancel可能にし、事実・branch・geometryには触れさせない。
  9. Phase 8 — 増築防止契約: architecture testsをCI対象にし、chronovisor-dashboard-check Skillへ全state screenshot、DOM/SVG geometry hash、console、全レーン検査を組み込む。新flow追加手順を「graph definition + event mapping + fixture」に限定する。
  10. Phase 9 — preview受入: previewだけを起動し、全scenario/frameを実ブラウザで撮影・実測する。差分contact sheetと失敗一覧を作り、ユーザーが確認できるURL/証跡を提示する。本番には触れない。
  11. Phase 10 — 完了整理: 不要コード・不要fixtureを削除し、関連test一式、static checks、preview smokeを再実行する。scoped commitsとPlanログを整え、明示依頼がある場合だけ別工程でpush → 本番再起動 → runtime SHA/health/live確認を行う。

Rollback

  • 各Phaseを意味のあるscoped commitにし、切替commitと旧経路削除commitの関係を実行ログへ記録する。
  • previewで重大な退行が出た場合は、混在した新旧経路を残さず、最後に完全整合していたcommitへrevertする。
  • production反映後に失敗した場合はdeploy commit全体をrevertし、push → restart → runtime archive SHA → health → live DOMを再照合する。
  • スクリーンショット、DOM/SVG manifest、test logはrollback後も保持し、原因をprojection / topology / renderer / runtimeへ分類する。
