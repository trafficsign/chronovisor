回復設計（2026-08-23 採用案）

採用案は、既存の run_distillation_chunk と Teacher runtimeを残し、その間を三操作の深い DistillationWorkset に置換する。 公開契約は advance（Raw差分をsealed generationへ進める）、claim（期限付きteacher workを取得する）、commit（結果を冪等確定する）だけにする。Raw全走査、全ledger読込、FTS全再構築、cursor、lease、retry、provenanceはこの境界の内側へ隠す。

現行経路の直接原因

  • _run_distillation_chunk_impl は各runで _events(raw_dir)、全rally抽出、manifest/candidate/labelの全読込、historical FTS全再構築を行い、candidate capture後に初めて教師へ進む。
  • append_chain_batch はappendごとに verify_chain で全ledgerを読み、さらに旧file全体を読み直して existing + encoded をatomic再書込する。candidate ledger 1.67GBでは一回のbounded appendもO(total bytes)である。
  • read_chain も全chain検証後に全fileを再読込してlist化する。watermarkやsidecarだけを追加しても、このwrite/read amplificationが残る限り根治しない。
  • snapshot完成とteacher完了を分離したdurable queueがなく、candidate_backlog=0でも未label workを直接claimできない。
  • schema不正をuncertain labelとしてcompletion扱いするため、壊れた出力がretryされず、有効label数と失敗attempt数が混ざる。

データの作り方

0. Feasibility preflight

  • P0で archive拡張子ではなくRawの実shape/receiptを検査し、native rally数、独立session/task cluster数、answer-utility eligible率、期間、host/session分布、exact structural/outcome link数、verified positive/negative/helpful/harmful発生率を数値化する。
  • P5のcandidate生成へ進むhard floorは、eligible native rally 1,000件以上・30日以上・3つ以上の時系列window、非probeのteacher label 500件以上・relevant/irrelevant各100件以上、3教師probe pair 100件以上、blind order一致のcounterfactual pair 100件以上とする。3 route/model digestは相互に異なることを必須にする。
  • 不足時はP1–P4のcapture/backfillだけを継続し、trainer・shadowへ進まない。probe一致や教師多数決をverified truthへ昇格せず、人手goldやlegacyからの推測でも不足を埋めない。

1. Rally manifest

  • rally-v1 の境界は決定的にする。semantic projection上の各non-empty user eventで開始し、次のnon-empty user event直前までのassistant連続turn、tool call/resultを同じラリーへevent順でfoldする。
  • Q_t は開始user event、K_t は同一sessionのそれ以前のsemantic event prefix、A_t はラリー内の実assistant semantic answerとする。元のRecall exposure/injection receipt集合 E_t もjoinし、assistant answerまたはexposure provenanceがないラリーはrelevance用には残せるがcausal answer-utility学習から除外する。
  • rally_id は host/session_key/raw_id/user_event_index/raw_sha/rally-v1 のcanonical hashとする。as_of は常に Q_t の時刻/indexで、A_t の時刻へ進めない。
  • 旧QueryManifestもuser eventごとだったため、RallyManifest自体がbase件数を増やすわけではない。増えるのは各ラリーから派生するcandidate/packet/answer-utility行であり、統計上の有効標本数は行数でなくsession/task cluster数として報告する。
  • manifestにはcontext/query/actual-answerのRaw range・hash・event refs、answer route/model revision、E_t receipt refs、eligibility reason、boundary revisionを保存する。本文は複製せず、教師実行時だけprivate RawStoreから再読する。
  • 教師へ渡す K_t は、P0固定の最大bytes内でevent境界を壊さない直近suffixとして決定的にrenderし、full prefix range/hashもreceiptに残す。
  • RallyManifest は学習ケースの正本であり evidence authority ではない。候補 Evidence は現行契約どおり assistant/tool/receipt に裏付けられたatomだけにする。
  • 同一内容の再実行は同じ id を返し、cursor は committed Raw watermark までしか進めない。

2. Historical index と point-in-time candidate snapshot

  • 候補条件は atom.validity.end < Q_t.time、または同じRaw/sessionの場合 atom.event_index < Q_t.event_index。同時刻はevent indexで裁定し、future leakageをfail-closedにする。
  • current Page/BM25/semantic/graph index は Q_t 後の更新を含むため、historical replay へ直接使わない。Raw/EpisodeProjection の assistant/tool atom だけから derived SQLite FTS5 index を watermark単位で決定的に構築し、atom id、validity、event index、exact path/commit/task/entity refs を保持する。
  • 候補は exact anchor、historical FTS BM25、receipt-bound relation を union し、教師用だけ top-K 100–300 を snapshot 化する。学習・評価対象はlive時点で利用できる K_t+Q_t だけから再現できる候補に限定する。A_t 由来の不足slotで見つけた候補はoracle missとして別記し、K_t+Q_t のretriever revisionで再取得できるまでstudent rowへ入れない。すべて同じ Q_t as_of filterを通す。
  • 初期版に別vector DBは作らない。lexical candidate recall が P0 gate を満たさない時だけ、同じatom集合から作るimmutable offline embedding generationを追加計画する。
  • candidate id、channel rank/score、atom/page refs、provenance、pool hash、retriever revision を保存する。候補生成と教師判定を分離し、後から同じ pool を再生可能にする。
  • historical FTS rank/scoreはcandidate discovery用であり、そのままstudent featureにしない。student featureはoffline/liveが同じ純粋関数とschema revisionで再計算できるものだけにし、byte-identical feature parity testを通す。
  • legacy archive、authority 不明、provenance 不一致、high-sensitive remote route は unknown/reject とし、学習対象へ入れない。

3. 三教師の割当

  • SHA-256("assignment-v2\0" + rally_id + "\0" + candidate_id) の固定bucketで主担当を決定的にほぼ均等化する。別の固定 probe-v2 bucketの15%だけ他の二教師にも送る。route/model更新でbucketを変えず、許容load skewはP0で固定する。
  • 全教師判定とblind counterfactualは teacher-only とし、三者一致でもverified truthにしない。probe対象のowner/追加route行はすべてtrainingから除外し、route安定性とdriftのlocked評価だけに使う。
  • strict JSON はtopic relevanceに加えて helpful | neutral | harmful | uncertain、不足slot、最小atom ids、変化するclaim、短い理由、route/model/prompt revisionを返す。入力はP0固定の最大bytes、最大候補数、候補ごとの最大Raw spanを越えない。parse failureは再試行せずuncertain。
  • 三者一致は model drift の観測値であり label authority ではない。probe の disagreement、flip rate、per-route calibration を比較し、劣化した route は自動停止できるようにする。

4. Answer-aware counterfactual utility

  • 実回答 A_t は不足claim slotを抽出する診断材料だけにし、A/B比較の片側にはしない。同じlocal generator・prompt revision・decoder設定・token budgetで、Evidence条件だけが異なるmatched counterfactual A0/A1 を生成する。
  • candidateが元のexposure E_t に無ければ A0=answer(K_t,Q_t,E_t)、A1=answer(K_t,Q_t,E_t∪{c})。既に含まれていれば A0=answer(K_t,Q_t,E_t−{c})、A1=answer(K_t,Q_t,E_t) とし、追加・除去の両方向で限界効用を測る。
  • 初期版はcandidate一件ずつの限界効用を測る。複数atomのEvidencePacketは単体効果を確認した後だけ1–3件に広げ、leave-one-out ablationで各atomが少なくとも一つのclaim変化へ必要か検証する。
  • A1 generatorとpairwise judgeは異なるmodel digestのrouteにし、stable roleをrally hashで循環させて負荷を均す。judgeにはcandidate armを渡さず、親だけがopaque A/Bとの対応を保持する。A/Bを交換した2順序の選択を候補armへ復号し、両方が一致した場合だけteacher-only信号へ採用する。
  • helpful はEvidenceにより正しいclaim・具体的判断・過去状態との整合が改善した場合、neutral は言い換え・長文化・既知内容の反復だけ、harmful は無関係・古い・矛盾・誤確信を増やした場合とする。
  • teacherのanswer-deltaはuntrusted train signalであり、route-separated locked replay、paired operational gate、認証済みnegative vetoを置き換えない。A_t/A1/gap/delta はlive feature whitelistで機械的に拒否する。

ライブ学生と速度設計

  • 新しい model service は作らず、既存pure Python logistic、readonly lexical candidate、policy sealを再利用する。
  • studentの予測対象はtopic relevanceだけでなく、質問とcandidateから推定する「将来回答への期待限界効用」とする。学習時の A_t/A1 はlabel生成専用で、推論入力へは含めない。
  • v2 featureは query_chargram_coverage と candidate_chargram_precision の2つだけにする。NFKC・casefold・英数かな漢字の3-gramを共通pure functionで計算し、historicalはQ_t+assistant atom、liveはprompt+canonical title/snippetへ同じ関数を適用する。cwd、時刻、rank、anchor、historical FTS scoreをstudent featureへ入れない。
  • P6a の authoritative path は既存 readonly lexical index の BM25/anchor だけで開始する。student は active JSON の重みを一回計算し、threshold と margin を越えた 0–3 cards だけ返す。

  • 新policyでは既存 usage_prior weightを0、旧 negative_feedback stageをhard offにし、sealed v2 policy以外からscoreを動かす経路を残さない。
  • SLO は end-to-end p50 ≤ 400 ms、p95 < 900 ms、hard deadline 1,200 ms、timeout < 1%。deadline 超過を timeout 延長で解決しない。

  1. Raw commit 後、sleep cycle の既存 bounded background lane が watermark 以後の新規ラリーを少量ずつRallyManifest化する。初回backfill中だけ既存30分Convergeから5分上限の同じchunkを追加実行し、完了後は自動で日次laneだけへ戻す。

  3. 各 cycle で point-in-time pool を作り、選択profileを処理する。local-triad-v1は三教師の決定的 shard/probe、ox-alpha-single-v1は独立workのsingle-teacher cohortとする。localはforeground Ollama leaseを最優先し、remoteは最大10件を並列推論してsingle writerへ返す。in-flight generationは短い上限内で完走させるか結果を破棄し、pause/resume可能とは仮定しない。

  7. 各段階で自動 gate が悪化を検出したら active pointer を LKG へ戻し、原因 run を quarantine し、学習を自動停止する。live 検索は LKG で継続する。
