Plan: Chronovisor Qwen3.8-Flash-Next 125B 一本化

ready plan_23f41aa9cef6401eae743d7fbfae7d32 2026-08-29T17:29:12+09:00

目的

結論: 旧 Qwen 27B / Gemma / Muse による3社合意を廃止し、選定済み Jundot/Qwen3.8-Flash-Next-oQ4e-mtp を、同じモデルの擬似3票ではない single_model_v1 権限として導入する。まず非変異 shadow で証明し、全 gate 合格後だけ ingest を含む変異レーンを有効化する。
  • 旧3モデルを参照する36個の生成 role と、8001/8002 の旧 provider 経路を125B/8000へ統合する。
  • 同一モデルへの repair / retry / self-review を独立票として数えず、監査証跡へ正直に記録する。
  • ベンチマーク時の速度・品質・メモリを本番 topology でも再現し、114,688 token の実運用上限を検証する。
  • Embedding / reranker / semantic / Ornith の補助モデルは今回の一本化対象外として維持する。
  • 失敗時は書き込みを止める。旧3モデルの重みは削除済みなので、設定復元だけを rollback 完了とは扱わない。

最小設計

  1. 既存interfaceを維持: DecisionRouter、LLMRuntime、LocalStructuredSessionを再利用し、新しいrouter階層やprovider抽象は作らない。
  2. modeを1箇所で分岐: DecisionRouterConfig.authority_mode に legacy quorum_v1 と新規 single_model_v1 を持たせる。singleは classification.authority 1 routeだけを解決する。
  3. proofを偽装しない: single proofは route identity、model revision、returned model、response digest、schema/effect checks、attempt履歴を持つ。repair回数をvote数へ加算しない。
  4. artifactをversion分離: 旧2-of-3 artifactは監査読取を維持するが、新policy下でreplayしない。single artifactは別 authority_kind / policy fingerprintで発行する。
  5. 段階的authority: shadow段階は全変異をhold。保存済みcorpus、実ingest dry-run、read-back、memory/soak gate合格後にだけsingle artifactへ変異権限を付与する。
  6. UIは既存経路を再利用: Dashboardの quorum_flow=false / single-artifact projectionを使い、3-role model resolverと表示文言だけをsingle route対応にする。

Phase 0 — Freezeと再現可能な開始receipt

Phase 1 — Single-model契約をtest-firstで実装

  1. DecisionRouterConfigへ authority_mode と単一authority roleを追加し、legacy quorumの3-route/distinct/quorum=2検証は変更しない。
  2. DecisionRouterをshared seamでmode分岐し、singleは1 call、最大2 repair、invalid/route drift/returned-model mismatchでholdする。
  3. authority、artifact、receipt、semantic holdへversioned single_model_v1 proofを追加し、旧artifactの読取互換と新policyでのreplay拒否をtestする。
  4. classification worker/engine/calibration/resource-burn、knowledge-graph producer除外処理をsingle route対応にし、vote/quorum由来の名前とmetricをsingle時に出さない。
  5. 旧3モデルの36 roleを上記移行ルールでremapし、補助8 roleが不変であるstatic testを追加する。
  6. LocalStructuredSessionの既存parse/schema/context/initial+2 repairを再利用し、Qwen4Expのcompat/reasoning/model identity tableを固定revisionへ更新する。
  7. Dashboard/Decision Traceの既存 quorum_flow=false 経路を再利用し、target=1、single authority、repair≠vote、model/revisionをAPI/DOMへ表示する。

Phase 2 — Offline検証とadoption候補artifact

  1. 関連unit/integration testとfull suiteをisolated CHRONOVISOR_ROOT で通し、ユーザーruntimeへ書き込まない。

  4. single adoption artifactを新policy epochへatomic publishし、旧quorum artifact、自己ラベルconsensus、不完全corpusを必ず拒否する。

この100件は量子化モデル比較ではなく、既存のproduction-likeケースを再利用するauthority回帰試験。新しい100問は作らない。

Phase 3 — Stable oMLX runtimeを単独で立ち上げ

  3. 旧Qwen/Gemma/Museのstale model_settingsと8001/8002 providerを除去する。bge/Ornithの設定はDFlash falseで保持する。

  5. /v1/models/status、status API、server logからmodel/revision/qwen4_exp/PLE mmap/Lightning MTP/context/memory ceilingをread-backする。

Phase 4 — oMLX実機gate

  3. 1件の実ingestをraw→apply→durable ack→read-backまで追い、再実行が重複applyしないことを確認する。

Rollback

重要: 旧3モデルの重みは削除済みで、即時のモデルrollback先はない。安全なrollbackは「旧3社合意へ即復帰」ではなく「新authorityを停止し、変異をholdしたまま補助経路だけを稼働可能にする」こと。
  1. Live前: oMLX専用serviceをbootoutし、config/settings/model_settings/plistをatomic restoreする。Chronovisorは停止のまま。stable weightは削除せず検証可能な状態で保持する。
  2. Shadow後: single adoption epochを無効化し、ingest/OXを停止、生成依存laneをglobal holdへ戻す。bge/Ornith/semantic/rerankerの非変異経路だけを必要に応じて復旧する。
  3. Live後: 新artifactとackを削除しない。policy namespaceでquarantineし、raw/page/state/read-backを照合して二重applyを防ぐ。コードはscoped revertし、GitHub-backed runtimeならpush後にrestart/archive/healthを再検証する。
  4. 旧構成が必要な場合: 旧Qwen/Gemma/Museのrepo ID/revisionをPlan evidenceから再downloadし、全shard/hash/structured/2-of-3 gateを通した後だけ復帰する。disk/time確保と明示承認が必要。
