目的

結論: 切替は確定済み。旧 Qwen 27B / Gemma / Muse による3社合意を廃止し、選定済み Jundot/Qwen3.8-Flash-Next-oQ4e-mtp の single_model_v1 へ、1回のmaintenance windowで全role・runtime・ingestを一括切替する。shadow、段階昇格、旧モデルとの再比較は行わない。
  • 旧3モデルを参照する36個の生成 role と、8000/8001/8002 の旧 provider 経路を125B/18125へ統合する。
  • 同一モデルへの repair / retry / self-review を独立票として数えず、監査証跡へ正直に記録する。
  • 切替後は125B単体のidentity、structured output、114,688 token、メモリ、実ingestを確認する。旧モデルを比較対象にしない。
  • 切替前に高速化候補を固定し、実測済みのANE hybrid prefillとprefix cacheを採用する。未対応機能を試験目的で本番設定へ混ぜない。
  • oMLXの配布・更新・process管理は公式DMG版へ一本化し、Homebrew版、古いsource checkout、独自oMLX LaunchAgentをruntime経路へ残さない。
  • Embedding / reranker / semantic / Ornith の補助モデルは今回の一本化対象外として維持する。
  • 失敗時は書き込みを止める。旧3モデルの重みは削除済みなので、設定復元だけを rollback 完了とは扱わない。

最小設計

  1. 既存interfaceを維持: DecisionRouter、LLMRuntime、LocalStructuredSessionを再利用し、新しいrouter階層やprovider抽象は作らない。
  2. active contractを置換: DecisionRouterConfig からprimary/challenger/tie/quorumのlive設定を外し、classification.authority 1 routeだけを解決する。切替後にquorum modeへ戻すtoggleは作らない。
  3. proofを偽装しない: single proofは route identity、model revision、returned model、response digest、schema/effect checks、attempt履歴を持つ。repair回数をvote数へ加算しない。
  4. artifactをversion分離: 旧2-of-3 artifactは監査読取を維持するが、新policy下でreplayしない。single artifactは別 authority_kind / policy fingerprintで発行する。
  5. 一括authority: code/config/serviceを停止中に完成させ、atomic config switch後の最初の起動からsingle artifactへ変異権限を付与する。部分的な旧route併存やshadow trafficは作らない。
  6. UIは1レーンだけ表示: Dashboardの既存 quorum_flow=false / single-artifact projectionを再利用し、authority_kind=single_model_v1 と quorum_flow=false を実行時の事実としてtraceへ保存する。現在の設定から表示modeを再推定しない。
  7. 3レーンは休眠保持: 現行の3レーンtemplate、SVG topology、renderer、projection testは削除しない。ただしsingle modeではPrimary/Challenger/Tie-breakのroute legend・lane・空き領域、NEXT VOTER、pair/tie/quorumのnode/connector/labelをすべて非表示にし、125Bのsingle authority laneを中央・全幅で描画する。
  8. UI toggleは作らない: operator向けの1レーン/3レーン手動切替は追加しない。休眠3レーンを再表示できるのは、将来承認されたquorum authorityが明示的なmodeをtraceへ記録した場合だけとし、legacy proofの存在や欠落roleから自動復活させない。

Rollback

重要: 旧3モデルの重みは削除済みで、即時のモデルrollback先はない。安全なrollbackは「旧3社合意へ即復帰」ではなく「新authorityを停止し、変異をholdしたまま補助経路だけを稼働可能にする」こと。
  1. Live前: 公式CLIでapp-managed oMLXを停止し、config/settings/model_settingsをatomic restoreする。Chronovisorは停止のまま。stable weightは削除せず検証可能な状態で保持する。
  2. 一括cutover失敗: 全Chronovisor serviceとapp-managed oMLXを停止し、staging前のcode/config/settings/model_settingsをatomic restoreする。ingest/OXと生成依存laneはglobal holdのままにする。
  3. Live後: 新artifactとackを削除しない。policy namespaceでquarantineし、raw/page/state/read-backを照合して二重applyを防ぐ。コードはscoped revertし、GitHub-backed runtimeならpush後にrestart/archive/healthを再検証する。
  4. 旧構成が必要な場合: 旧Qwen/Gemma/Museの再取得はこのcutoverのrollbackに含めない。別作業としてrevision固定downloadと完全性確認を行う。
